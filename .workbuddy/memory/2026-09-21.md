## 调研：OsmAnd 的跨区域处理（及能否用到 navimap）

源码在 /home/along/osmand-app（8.6G 全量，核心 C++ 在 OsmAnd-core/，现代 Java 路由在 android/OsmAnd-java）。

### OsmAnd 三层做法（核心是"按需取数"，不是"全部加载再遍历"）
1. **集合层** `IObfsCollection`（include/OsmAndCore/IObfsCollection.h）：每个地区一个 .obf。
   `obtainDataInterface(pBbox31, minZoom, maxZoom, dataTypesMask)` 是关键——
   ObfsCollection_P.cpp 里对每个候选文件调 `obfInfo->containsDataFor(...)`，
   **不相交的文件连 fopen 都不做**（obfInfo 已缓存时连 open 都省）。
2. **渲染去重** `ObfMapObjectsProvider_P.cpp:701-808`：一个瓦片的数据来自所有 obf，
   按 **ObfObjectId（= OSM id）** 把重复对象分组；排序规则 = BinaryMapObject 优先于 Road，
   再按**地图日期越新越前**；`zoom <= ZoomLevel14` 时**保留**来自不同地图且首末点不同的重复者
   （那是边界两侧被各自裁剪的两半，都要画），`zoom > 14` 只留最新一份。
   缓存键 `UniqueBinaryMapObjectId(blockId, objectId)`——承认 id 只在文件内有意义。
3. **★ 路由：节点主键就是坐标**（最值得抄的一招）
   `RoutePlannerContext.cpp:132`： `uint64_t id = (x31 << 31) | y31;`
   `RoutePlanner.cpp:250-293 loadTileHeader` 遍历**所有 sources**，用 querySubsections
   收集覆盖该 tile 的**所有 subsection（跨文件）**；
   `RoutePlanner.cpp:1371-1412 loadRouteCalculationSegment` 对同一坐标遍历所有 subsection
   取分段串成链表 ⇒ 一个"图节点"= 所有文件里落在同一坐标上的所有分段。
   ⇒ **跨区不需要任何节点 id 映射表**。生成时写的是整数坐标，边界两侧天然一致。
   另有 `_indexedSubsectionsContexts` + `memoryUsageLimit` + `unloadUnusedTiles` 做 LRU 换出。
   BorderLine/ObfRoutingBorderLinePoint 是 A* 启发式修正用（注释 "FIXME borders approach"），
   **不是**缝合机制，别看错。

### 不要抄的部分
- **HH/CH 层次化路由反而是"选而不并"**：`HHRoutePlanner.java:643-700 selectBestRoutingFiles`
  把所有相交区域按 含起终点 > 新版 > 参数匹配 > 相交面积 排序，**只挑 bestGroup 一个组**。
  一旦要预处理加速图，跨区就是退让，不是合并。

### 由此查出的本项目真问题：各省数据互相包含，北京被画两遍
用 osmid.bin（NM_KIND_OSMID=5，per-node int64 OSM id，跳过 512B 前导）两两求交：
- **beijing ⊂ hebei 100.00%**（4,322,181/4,322,181），**tianjin ⊂ hebei 100.00%**（1,652,737）
  —— 下载的省份提取是矩形/多边形裁切，河北聚多边形把京、津整块包进去了。
- 其余相邻省是正常边界重合 0.16%~4.35%（共享跨界 way），非相邻省 0%。
- 后果：z16 北京渲染 edges/areas/lines 全部**精确 2.0 倍**（1890→3780 等），
  帧时间 269ms→681ms（2.5x）；磁盘浪费 332MB / 1.9GB（17.5%）。
- **决定性验证**：仅加载河北 vs 仅加载北京，同一位置 z16 渲染的 BMP **md5 完全相同**
  （d402fae3…）⇒ 两份数据几何逐字节一致，画两遍零收益。

### 顺带修掉的两个同类 bug（统计归属）
`paint_areas`(344) / `paint_lines`(428) 里有 `st->areas_drawn = 0` / `st->lines_drawn = 0`，
多省循环时每个省都清零一次 ⇒ 最后一个不覆盖视口的省把计数清成 0。
表现："8 省加载时 areas_drawn=0，单省 1093"。已删，规则维持：**一帧只在 paint_frame 开头清一次**。
（第三次踩同一类坑：挨个层"顺手清零"会把别的层的累加结果抹掉。）

### 结论：下一步可直接用 OsmAnd 的方案
- 渲染去重：id 用边两端 OSM node id 有序对（我们没有 way id，只有节点 osmid.bin）。
- 跨省路由：**不要做全局节点合并表**，改坐标键 `packed(x,y)` + 每省"坐标→节点下标"索引
  + 按 tile 查所有省。增量友好（加一个省不用重建 2.4GB）。

- **DedupSet**（paint.h/c）：128 位键开放寻址 + 世代标记（换帧 ++gen 不清表）。
  身份键：边=两端 OSM 节点 id **有序对**（★不能 min/max 排序——双向路回程边会被
  误判重复、整条路消失）；线/面=自带 OSM way id（LF_OSM_ID/AF_OSM_ID，
  实测 8 省 0 条为 0）。只在 ≥2 省盖住视口时启用，单省 NULL 快路径。
- 回归：单省 md5 逐像素一致（dedup_skipped=0）；全国 z9 跳 14.3 万重复；
  京津冀 z12 拦 6.97 万（帧 230→191ms）。顺带修了长边跨 tile 重复登记的
  同省重画（z16 北京 1890→1818 唯一边；多画的 72 条像素相同无视觉差异，
  与单省渲染差 12 个像素 = 标注避让顺序不同导致的文字 AA 微差）。
- **coordkey.h**：coord_key_e7(lat,lon) 打包 u64（学 OsmAnd (x31<<31)|y31）。
  **mapset_query_tile()**：按 tile 遍历所有省的空间索引（= OsmAnd loadTileHeader）。
  **tile_xcheck**：验证工具。★踩坑：mapset_query_tile 一次遍历所有省，
  外层不能按循环 i 归属省份——回调自带的 s 指针才是身份（按 s-ms->srcs 算下标），
  否则所有省的边都记到同一个省名下，共享坐标数虚增 8 倍。
- 实测冀津交界 tile：7 个缝合点，OSM id 全一致，本地下标全不同
  （hebei:#9768464 vs tianjin:#901054）→ 坐标键路由前提成立，阶段 8 可直接开工。

## 落地：阶段 8 跨省路线计算（src/route/route.{h,c} + tools/route_cli.c）

- **状态主键 = 坐标 coord_key_e7，不是 (省,节点)**。初版 (省,节点) 主键 +
  "同坐标成员一起 settle"：北京→天津 展开 111 万、97 秒、路径在京冀副本间
  抖动 560 次。改坐标键（OsmAnd id=(x31<<31)|y31 的本意）后一个物理路口一个
  状态：57.5 万展开、抖动归零。教训：合并组 ≠ 共享状态，重复副本必须
  在"状态"这一层消除，不能在"展开"这一层。
- **数据包含检测**（detect_duplicates）：bbox 包含 + 节点数更少 + edgelist
  抽样 1000 点 ≥99% 在对方 tile 索引命中 → 判包含。自动识别 beijing/tianjin ⊂
  hebei（与 osmid 全量求交结论一致）。路由展开跳过副本省：北京→天津 46.8s→0.62s。
  ★ 采样必须从 edgelist 取：按节点表采样会把"只有入边"的节点算进去（瓦片索引
  只登记 from），命中率掉到 60% 漏判。
- A* 启发式必须用 nm_haversine_m；nm_fast_dist_m 是等距投影近似，跨纬度大时
  高估破坏 admissible。
- 瓦片缝合缓存 256 槽；先只读瓦片目录统计"去重后有效省数"（dup 省映射到宿主
  去重），≤1 就完全不建索引——热路径最大开销省在这。
- ★ StEnt 数组会 realloc：StEnt* 严禁跨 st_intern 持有（intern→用完→重新 find）。
- ★ 路径重建：段 i 的边 = pts[i+1] 的 prev_edge（语义"前驱→我"），取 pts[i] 的
  会整体错位一格 + 起点的默认 SEAM 被当成接缝（踩过）。
- ★ "--x=" 前缀比较长度错第三次出现，route_cli 里改用 arg_val(a, prefix)
  （strlen 内部计算），以后新工具一律用它。
- 验收：城内 8.27km/11ms；京→津 131.85km/0.62s；京→郑 693.65km/16.3s（绕行 1.11）；
  郑→济、西→郑 全过；海上负向正确报无路。视觉验收：map_shot --route= 叠加红线，
  起终点均贴路网（docs/shots/route_bj_start_z14.png / route_tj_end_z14.png）。
- 遗留：长途 16s/1.3GB，需双向 A*（反向 CSR）或分层路由；跨省接缝跳过限制检查
  未验证；GUI 尚无路由入口（阶段 9）。
