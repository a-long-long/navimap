# 2026-10-24 工作日志

## 方案2 收尾：去 SDL 化落地 + 三条新门禁

### 架构（已完成，编译零警告）

```
navimap_core   = plat/paint/raster/navdraw/chrome/font/labels/window(业务层)  ← 零 SDL
navimap_sdl    = window_sdl.c（SDL 窗口/事件/离屏画布/app_run）             ← 唯一碰 SDL 的库
map_shot        = 自己 include SDL.h（存 BMP + 像素统计），不链 navimap_sdl
navmap_qt       = navimap_core + Qt Widgets，**一行 SDL 都不碰**
```

- `App` 里的 SDL 字段（win/win_ren/tex/ren/surf）+ `Raster ras` **全部删掉**。
  Raster + 帧缓冲改由 `window_sdl.c`（离屏 surface）和 `navimap_qt`（QImage）各自持有。
- `app_render_to_surface(SDL_Surface*)` → `app_render_to_buf(px, w, h, stride, r/g/b/amask)`。
  **像素格式一律从 surface 自己的 format 读，不写死**（写死会"红蓝互换"且只在别人机器复现）。
- `chrome_act` 里 `CH_WIN_MIN/CH_WIN_MAX` 的分支删了（核心不能碰 SDL），
  由 `window_sdl.c` 的 `sdl_window_action()` 截住 —— ★**这个洞一开始漏了，
  最小化/最大化按钮会失效**，靠"注释写了 ≠ 所有路径落实"抓出来。

### ★ 三个真实的像素级 bug（都是自写光栅与 SDL 不等价）

1. **alpha 混色公式**：SDL 是 `(s*a)/255 + (d*(255-a))/255`（两次除法），
   我们原先是 `(s*a + d*(255-a))/255`（一次除法）→ 13.9% 色值差 1 级。
   修法：`blend_ch()` 拆成两次除法。
2. **`raster_rect` 角点被混两次**：4 条边在角上重叠 ⇒ 角点混两次、SDL 只混一次。
   修法：角点只画一次。
3. **线段裁剪与 SDL 不等价 34.3%**：手写 Cohen-Sutherland 与
   `SDL_IntersectRectAndLine` 在越界线段上差 1 像素（症状：画布边缘的路多/少一像素）。
   修法：按 SDL 的 `src/video/SDL_rect_impl.h` 逐字重写（水平/垂直短路 + 早退 + 差值方向）。

⇒ 逐像素比对从 **1.784% → 0.237% → 0.066% → 0**（地图+chrome 与 HEAD 基线**完全一致**）。
带字时 819 px (0.171%)，全部是字形抗锯齿（stb_truetype vs SDL_ttf 的预期差异）。

### 新增回归门禁（regress.sh 里 4 项，全绿）

| 门禁 | 工具 | 判据 |
|---|---|---|
| `blend_equiv` | tools/blend_equiv.c | 填充/描边/线段/单点 与 SDL 软渲染器逐像素一致 |
| `clip_equiv` | tools/clip_equiv.c | 20 万随机线段与 SDL_IntersectRectAndLine 完全一致 |
| `core_no_sdl` | tools/core_no_sdl.c | navmap_qt + libnavimap_core.a **零 SDL 符号** |
| `core_no_sdl_sdl` | 同上 `--expect-sdl` | navimap **必须**有 SDL（负向对照） |

★ **负向对照全部实测过**（注入偏差 → 必须失败 → 恢复）：
- 混色公式改回旧写法 → blend_equiv 报 265 px 差异、FAIL
- 裁剪交点 +1 px → clip_equiv 报 39% 不一致、FAIL
- 把 SDL 版当核心 / 把 Qt 版当适配层 / 文件不存在 → core_no_sdl 三种都 FAIL

### ★★ core_no_sdl 的两个坑（写工具时踩的，值得记住）

1. **`nm -u <PE exe>` 不列 DLL 导入符号**（只有 3 行 CRT 的 __tls_*）——
   Windows 的 SDL_CreateWindow 之类在 **objdump -p 的导入表**里。
   ⇒ 必须 `nm -u` 与 `objdump -p` **两个提取器取并集**，只跑一个会在另一个平台静默漏检。
2. **假绿**：最初用 `2>&1` 把 stderr 混进 stdout，于是命令失败时的错误行也凑出了
   `total>0` ⇒ 判成"提取成功且无 SDL"。实测把 SDL 版 navimap.exe 传给
   "期望无 SDL"判据，它报了 OK。⇒ 判定必须用**退出码**（`pclose` 的返回值），
   stderr 单独重定向到临时文件（`nm_temp_dir()` + pid），失败时把原因读出来报。
3. MinGW 的 `popen` 走 **cmd.exe**：带引号的可执行路径必须加 `call` 前缀；
   `2>/dev/null` 是无效重定向（会整条命令失败）。

## 追加：Qt 前端中文变方框（tofu）的定位与修复

### 现象与定位（J 先生报的"字体变成方框了"）

Qt 前端截图里所有中文都是方框。但**只有 Qt 控件**是方框：
- 地图上的文字（C 侧 stb_truetype 画的）**完全正常** —— "搜索地点、道路…"、
  "浏览/导航"、"20 公里" 都清晰；
- Qt 控件文字（菜单/页签/搜索框占位符/右栏）全是方框。

原因：**两套字体系统互不相干**。
- 地图文字 = C 侧 `render/font.c`（stb_truetype），字体来自 `plat.c` 的
  `nm_font_candidates()`（自带 DroidSansFallback.ttf）；
- Qt 控件文字 = Qt 自己的字体系统，**什么都没注册** ⇒ 没中文字体的环境
  （Linux 容器 / Qt offscreen 插件 / CI）就变方框。

⚠️ 我第一轮把这归因为"offscreen 模式的问题，与本次改动无关" —— **错了**，
是真实的 bug。教训：截图里出现方框时，先分清"哪一层画的"，别急着甩锅环境。

### 修复

新增 `src/ui_qt/qt_font.{h,cpp}`：
1. 遍历 `nm_font_candidates()`，`QFontDatabase::addApplicationFont()` 全注册；
2. 挑出**确实含中文字形**的族；
3. `QFont::setFamilies()` 设成中英回退链，让 Qt 自己做 per-glyph 回退。

★★ **判"字体能不能画中文"不能用 Qt 的字体度量**（踩过）：
   量"中"字宽度、跟无中文的参照字体比宽度 —— 在 **Qt offscreen 插件下不可靠**：
   该插件不走真实字体引擎，所有族宽度都一样 ⇒ **每个族都判成"没有中文"**
   （实测 Noto Sans / Droid Sans Fallback / 微软雅黑 全部判否）。
   另一个坑：`QFontInfo::family()` 返回的是 Qt **实际替换后**的族名，不能判"族是否存在"。

   ⇒ 可靠做法：**查字体文件本身**（C 侧 stb_truetype 的 cmap）。
   新增 `font_probe_glyph()` 诊断接口 + `tools/font_probe.c` +
   `tools/font_cjk_check.c`（回归项），判据是
   **glyph index 非 0 且光栅化后非零像素 > 0**（只看 index 会漏"有字形但画不出"）。
   实测：`DroidSansFallback.ttf` 命中 18/18，NotoSans 命中 0。

修复后选中的是**自带的 Droid Sans Fallback**（不是系统雅黑）⇒ 不依赖系统装字体，
任何机器都能工作。

### ★★★ Windows(MSYS2) 上 gcc 静默失败（本轮最耗时的坑）

**现象**：ninja 在 Windows 上通过 cmd.exe 跑编译命令时，gcc/g++ **退出码 1、
stderr 一个字都没有**。看起来像"代码编译不过"，其实代码完全没问题 ——
项目里**原有的** main_window.cpp（本次没碰过）同样编不过，
而 `cc1plus.exe` 单独直接跑 100% 成功。

**逐项排除后的结论**（每条都实测过）：
- 参数、宏、输出路径、工作目录：**全部无关**（同样命令时好时坏）；
- `nm -u <PE exe>` 不列 DLL 导入符号（那是 core_no_sdl 的另一码事）；
- **PATH 形式**：MSYS 形式 ⇒ 成功，Windows 形式 ⇒ 失败。
  MSYS runtime 把环境传给原生程序时会转换 PATH（`/d/...` → `D:/...`），
  ninja→cmd.exe→gcc 这条链上拿到的是转换后的 PATH；
  用 `env PATH=<MSYS 形式>` 启动则**绕过**转换 ⇒ 稳定成功（12/12）；
- **Defender 实时防护**（MsMpEng 常驻数百 MB）会扫描新起的 cc1plus.exe 并
  偶尔**直接杀掉**它 ⇒ 又是"退出码 1、零输出"。加 `sleep 0.3` 后 10/10 成功。

**最终解法**（三件套，已进仓库）：
- `scripts/build_launcher.bat` —— CMake 的编译启动器，把每次编译转到
  MSYS2 的 sh 里跑（绕开 cmd.exe）。**必须用 target 属性**
  `C_COMPILER_LAUNCHER` 而不是 `CMAKE_C_COMPILER_LAUNCHER`：后者是
  **初始化变量**，只在首次 configure 生效 ⇒ 已有 build/ 的机器改了也不生效
  （实测设了但 ninja 生成的命令里根本没有它）。
  ★ .bat 文件**必须纯 ASCII**：cmd.exe 读 .bat 时会把非 ASCII 注释当命令执行
  （中文注释直接导致构建失败）。
- `scripts/cc_retry.sh` —— 重试包装器：失败且 **stderr 为空** ⇒ 判定被 Defender
  杀 ⇒ 递增延时重试（最多 8 次）；失败且 **stderr 非空** ⇒ 真编译错误，
  立刻报出（不用重试掩盖）。
- `scripts/build_win.sh` —— 一键构建：受控 PATH + `-j4`（低并发降低 Defender
  触发率）。

### 顺带修的

- `src/render/font.c` 加 `Face.path` 字段（诊断用）与
  `font_probe_face_count/face/glyph` 三个诊断接口；
  `font_close` 里释放 path（strdup 副本）。
- `tools/font_probe.c`（字体诊断探针）、`tools/font_cjk_check.c`（回归项）。

### 回归

- 新增 2 项门禁：`font_cjk`（字体链必须有 CJK 字体）、
  `font_cjk_neg`（**检测逻辑本身**正反两侧都对 ——
  用"藏起字体"那种对照是假的，系统字体还在，判据照样过）。
- 回归：30 通过 / 23 失败（23 个失败与基线**逐项一致**，全是本机缺数据）。
- **像素等价重新验证**：与 HEAD 基线（SDL_ttf + SDL 渲染）**0 像素差异**
  （地图+chrome，48 万像素全等）。基线的构建过程正好印证了方案2 的价值：
  基线 map_shot 必须链 `SDL2_ttf`，现在不需要了。

⇒ 新增 `src/ui_qt/qt_icons.{h,cpp}`：`QPainter` 自绘矢量图标

★★ **坑：drawPixmap 在 DPR≠1 下会把图标画到目标矩形的一角**。

（放大镜只剩左上弧、三横线只剩两条）。
- `QPixmap::scaled()` **不保留 devicePixelRatio** ⇒ 缩放后逻辑尺寸翻倍、被裁。

⇒ **正解：不用 pixmap 中转，直接在 `paintEvent` 里用 QPainter 画路径**
（`qt_draw_icon(p, kind, size)`）。见 `src/ui_qt/qt_icon_button.hpp`。

### ★★ C 侧拆文件踩到的坑（每条都实踩）

1. **忘了 strip `static`** ⇒ 「static declaration follows non-static」：
   如果函数要被原文件调用、声明进 X.h，那它在 X.c 里必须去掉 static；
   只在本文件用的（sort_kv / sew_cb / cmp_pn / lm_prov_of）才留 static。
2. **私有类型不能随模块头搬走**：SewEnt/SewSlot/SEW_SLOTS 一旦放进 sew.h，
   而 struct Router 又要 SewSlot ⇒ route_priv.h 必须 include sew.h，于是
   **谁先被包含都会出现"类型未定义"**（sew.h→route_priv.h→sew.h 环，guard 让后半段变空）。
   ⇒ 定式：`restr.h`/`sew.h` 一律 **include route_priv.h**（拿到完整 Router 和类型），
   类型本身留在 route_priv.h 不动。
3. **`route.h` 不能放完整 Router**：它被 render/ui 包含，泄漏会把
   mapset/st/pqueue/revidx/lmtable 一整套头文件强加给渲染层 ⇒ 私有头 `route_priv.h`
   只给 route 模块内的 .c 用（lmtable.c/revidx.c 只用 Router 的不完整类型，不需要它）。
4. **声明要放在类型定义之后**：members_of 用了 SewEnt，插到 SewEnt typedef 之前
   会编译失败（第一次就插错位置）。
5. **共享宏要下沉**：MAX_MEMBER 被 members_of/expand_dir/lm_dijkstra 三方共用 ⇒
   搬到 route_priv.h；判断"是否共用"要 grep 全部使用点，别想当然（我一开始以为
   只有 search 用，实际 lm_dijkstra 也用）。
6. **搬迁脚本必须有双向断言**：该消失的（旧定义）**和该保留的**（调用点、类型用法）
   都要 assert；单次 assert 拦截是在写盘**之前**，所以脚本崩了工作区是干净的。
   ⚠️ 但脚本**漏写 `write()` 调用**这一步拦不住（cost.c 那次就是没生成文件、
   route.c 却已调用 ⇒ 必须 `ls` 确认新文件真的落盘再编译）。
7. 锚点用**唯一子串 + assert count==1**，不要用"找下一个 `}`"定位函数结尾
   （会拿到内层 sort_kv 的 `}`）；用下一个**段落标题**做右边界更稳。
