## 实现「只留 PBF，显示层按需解码 + LRU 缓存」（用户指令）

用户诉求（承接 10-22）：硬盘别同时存 PBF 和 nmbin；运行时只加载屏幕区域，滚出再加载别的。
选定路径：**显示层（面/线要素）从 PBF 运行时解码 + 内存 LRU**，路由图仍走 nmbin。

### 关键设计决策（都是实测驱动的，不是猜的）

1. **省粒度而非瓦片粒度**：实测 PBF 的 data blob 平均覆盖全省 43% 纬度跨度
   （北京 621 个 blob，单个跨 0.99°/1.33°，**z11 视口仍命中 53%**）⇒ 按 blob 跳读
   收益低于索引成本，**不可行**。改为"整省解一次 + LRU"。
2. **不需要扫第二遍 PBF 取坐标**：`polyrefs` 存的是节点内部下标，而这个下标空间**就是**
   nmbin `nodes.bin` 的下标空间（都按 osm_id 升序、都去掉了文件里不存在的节点）
   ⇒ 拿 nodes.bin 的 osm_id 数组做**二分查表**即可。**省掉整遍 PBF 扫描（河北约 4 s）
   与两份坐标数组（河北 105 MB）**。这一条把峰值 RSS 从 1.5 G 降到 714 MB。
3. **PBF 的 dense 节点 id 严格升序**（天津/北京/河北实测 0.0000% 逆序或重复）——
   曾用哈希表对齐，改成双指针归并后：河北 12.7 s→9.6 s、1.53 G→1.14 G。
4. **下标空间必须与 graph_build 一致**，两处收集规则：
   - refs 收集**要含路网 way 的节点**（graph_build 在"路由/线/面"三分支**之前**就累加 refs），
     少收一类 ⇒ 下标错位 ⇒ 坐标全错（我第一版就踩了，表现为坐标整体移位一位）；
   - 名字池 id 空间要与落盘版一致 ⇒ **路网 way 也要 intern 名字**（虽然不建记录）。
5. `polyrefs` 的下标来自 nmbin 的 nodes.bin ⇒ **polyrefs 逐字节相同**，
   但**不能拿自己的 polyrefs 配自己的 nodes**（下标空间会错位）⇒ 必须用 nmbin 的 nodes。

### 实测数字

- 解码耗时：天津 0.65 s / 北京 1.6 s / 河北 4.4 s（**同步**，首次进省会停顿）。
- 峰值 RSS：天津 104 MB / 北京 275 MB / 河北 714 MB。
- 等价性：**8 省 areas/lines/polyrefs 逐字节 IDENTICAL**（含 4000 万节点坐标）。
- 磁盘收益：**195 MB**（8 省 lines+areas/polyrefs）。
- 渲染统计两模式完全相同：areas 21839 / lines 1053 / edges 77819 / place_labels 61。

### ★ 顺带发现一个既有的渲染缺陷（与本功能无关，但被它暴露）

PBF 模式与 nmbin 模式的**文字最终像素**差 12.357%。用对照实验证明**与 PBF 数据无关**：

- 用 nmbin 显示层 + **同样的堆布局扰动**（解 PBF 但不挂载）⇒ **复现同样 12.357%**；
- **ASan（-O1）构建下 0 差异** ⇒ 优化器相关的未定义行为（ASan/valgrind 查不到，
  不是 use-after-free）；
- 差异**只在标注阶段**（地名 8.8% + 路名 3.2%）；面/路/线三阶段 raster **逐字节相同**；
- 文字绘制调用（文本+坐标）**完全相同**（362 次逐字一致）⇒ 差异在字形纹理合成本身。

⇒ 结论：**既有的、依赖内存布局的文字渲染不稳定缺陷**，任何改变堆布局的改动都会暴露它，
需要单独修。已写进 PROGRESS.md「已知限制」并列为下一阶段第一优先。

### 踩的坑

- **本机 git 2.20.1 太老**：`git init -b main` 不支持（2.28+）⇒ `git init` +
  `git symbolic-ref HEAD refs/heads/main`；`git branch --show-current` 同样不支持。
- **本机 shell 会吞掉 `NAVMAP_*` 环境变量**（`PATH` 传得进、`NAVMAP_XXX` 传不进）⇒
  调试开关一律用**文件标记**（`access("/tmp/xxx", F_OK)`），别用 getenv。
- **清理探针时 python 补丁的删除边界算错，把 `labels.c` 整段误删**（-111 行）
  ⇒ 用 `git checkout --` 恢复；教训：批量改文件后立刻 `git diff --stat` 核对。
- `pbfmap_decode` 早期版本用 `sp_intern` 但 `StrPool` 与 `NamePool` 是**不同类型**
  ⇒ 显示层不需要名字池（`LF_NAME_ID` 全代码库**只写不读**），但为了与落盘版逐字节
  相同仍要 intern（路网 way 也要 intern，见上）。
