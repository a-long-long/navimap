## 性能口径 + 判据纪律

- **渲染**用 `map_shot` **第二帧**；**算路**用 `route_cli --repeat=N` **丢第 1 次**取中位
  （"搜索 X ms"含反向索引构建，端到端 real 才含图加载）。
- 无 `perf`/valgrind；`clock_gettime` 52 ns ⇒ 插桩会污染（渲染探针自吃 5~8 ms），量完撤干净再取基线。
- ⚠️ **负载能污染算路耗时一个数量级**（load≈10+swap 满：502→3885 ms，展开数不变）
  ⇒ ★ **布尔判据用展开数/里程/像素，别用耗时**；时间只兜底且取多轮最小值。
- ★★ **A/B 至少 4 轮，每轮都列出来**。
- ★★★ **"手挑几条代表路线"下结论必翻车，已踩 4 次**（§50.7 6 条说"w=1.2 占优"、44 条中位反；
  §51.4 8 条说"快 5.7 倍"、50 条全量**中位慢 1.8×**）
  ⇒ 样本必须**覆盖形状且成对配对**，报结论前先问"难走/好走各占多少"。

## 数据格式：PBF vs OBF

- navimap 只吃 `.osm.pbf`（自写 `src/pbf/` 解码 → 自编 `.nmbin`）；**零 OBF 代码**。
- ★ **磁盘构成实测**：PBF **446 M**；nmbin **4.2 G**，其中**显示相关仅 ~19 M/省、94% 是路由图**
  ⇒ "删 nmbin 省空间"只省得到那 19 M/省，**真吃盘的是路由图**（A\* 需全图，省不掉）。
  ⇒ **nmbin 值得保留，可以不演化 v3**（v3 只 z9 −16 ms，不抵 +139 MB）。
- **不要为 POI 引入 OBF**：`places_build.c` 早已从 PBF 抽 amenity/shop/tourism/... 进 `place` 表，
  `labels.c:kind_max_for_zoom()` 在 z≥15 返回 12 正好覆盖 ⇒ POI 已可见/可搜。
- 授权：借鉴思想 + 注明出处 + 不同语言/框架独立实现 = 最干净路径（coordkey.h 已示范）。

## 渲染：定论与"别再试"

- **多省不变量**：多省画面 == 只加载包含方的画面（8 省 vs 只河北 0 差异），可当验收。
  被整省包含的省（`dup_of>=0`）面/路/线全跳过；去重只在"这格瓦片 ≥2 省"时做；**面/线不去重**。
- ★ **"简化几何"一律不成立**，已否决三种，别试第四种：投影前按像素筛顶点 /
  Douglas-Peucker（ε=0.5 就 1.1% 差异且**更慢**）/ 放宽 AREA_DOT_PX。z9 走完整管线的面 **91% ≤5 px**。
- 同样别再试：去掉描边、面要素加 tile 索引、顶点内联进索引、软件预取、缓存上一条目起点、
  合并连续边成折线、**NMBIN 内存布局 v3**。★ 贵的是**间接寻址**不是 stride。
- ★ **只有"不画"才省得下来**：SDL 每次绘制调用固定 ~100 ns，与像素数无关。
- ★★ 自写像素（`src/render/raster.{h,c}`）后：**退化段（两端同坐标）必须画 1 个像素**。
  本机 surface 是 **`SDL_PIXELFORMAT_RGB888`**（Amask=0）。
- ★★★ **销毁 renderer 前必须 `font_drop_textures()`（font + font_big），每条销毁路径都要**
  （2026-10-23 修的既有 bug：文字像素错乱 12.357%）。
  `glyph_get` 靠 `tex_owner != r` 判"renderer 换了没"，**判据是指针相等** ——
  `SDL_DestroyRenderer` 把内存还给分配器，下一帧 `SDL_CreateSoftwareRenderer` 很可能
  **拿回同一地址** ⇒ 判据失效 ⇒ 缓存里 `g->tex` 成**悬垂指针** ⇒ 字画错。
  ★ **这类 bug 只在特定堆布局下显形**（改任何影响分配顺序的东西都可能触发），
  **ASan/valgrind 查不到**（不是 use-after-free）。**注释写了约定 ≠ 所有路径落实了**。
- 面要素 55 ms 已逐段量完（投影 21/填充 13/描边 10/访存 6/固定 9/遍历 3），无明显空间。

## 算路：约定与已做

- **默认加权 A\* w = 1.4**（无表）；与 `opt.exact` 是两个独立旋钮。★ 这是**产品行为**。
  ★ 兜底是 `mode_time=1` ⇒ **优化时间不是里程** ⇒ 质量指标必须用"预计 X 分"，
  **不能用里程/绕行系数**。档位：w≤1.2 无损；**1.4 是拐点**；1.5 起真劣化。
- **自适应 w**：第 1 遍基准 w + 封顶 `ROUTE_ADAPT_TRY=20 万`；顶内结束与基准 w 逐位相同，
  撞顶才换 `ROUTE_HEUR_W_HARD=1.8` 重跑。判据是**展开数 < 100 万**。★ 对拍时 `heur_w_hi` 也要设。
  ★★ **加 w 救不了尾部**：1.8→3.0 时间最多再降 1.9×，质量 +9%~+37%，**大连→北京非单调**。
- ★ `RouteOpts` 一律**指名初始化**。★ **热路径严禁 `getenv`**（一次 135 ns），
  调试开关用 `static int f(void){static int v=-1; if(v<0) v=...; return v;}`。
- ★ 拆函数改了共享状态必须恢复：`plan_search` 曾把 w 写进 `r->opt.heur_w` 没恢复
  ⇒ `--repeat=N` 第 2 次起假数字。
- **反向索引已落盘** `rev.bin`（8 省 355 MB）；没有/坏了自动现场建。默认只做 O(1) 校验
  （全量 FNV +554 ms 比重建贵，`NAVIMAP_REV_STRICT=1` 开严格）。
- rev.bin v2（存 edge_idx）：**做完、实测否决、已回退**（只值 3%，+146 MB）。
  ★ 每个反向条目 unavoidable 的冷访存就是两次，v1/v2 都是两次，**没有第三次。别再试。**
- **瓦片下标查表化** `tileidx.{h,c}`。★★ **回退带（2e-3 瓦片）必须大于查表误差**
  （墨卡托 `y''∝1/cos²φ`：45° 3.8e-6 → **85° 3.6e-4**）。
- **`SEW_SLOTS`=16384**，容量参数要用**工作集最大**的输入定案。
- `DEFAULT_MAX_EXPAND` **1200 万**（800 万会剪断真实路线）。★ 边际 ~210~290 B/展开。
- **状态表**：`StSlot{uint32 h; uint32 idx;}` 一个数组 8 B/槽（h = mix64 高 32 位|1，
  命中后用 `ents[idx].key` **回验**）+ 追加式 `ents[]`（StEnt 48 B）。
  ★ **大搜索里 st_probe 占 28%**，是**串行依赖的随机访存延迟**
  ⇒ 只有**减少 relaxation 次数**才动得了它。**别再改布局**（合并结构体数组 24/16 B 三连败，
  stride 翻倍 = 探测路径 cache 减倍）。唯一没试：settled 塞进 `val` 高位。
  ★ 结构体大小**用 gdb 量**（心算错过一次）。
- **优先队列**：`src/route/pqueue.h` 四叉堆 `PQ_D=4`。★ **别再调叉数**（D=2 36.4 / D=3 24.7 /
  **D=4 13.2** / D=5 19.3 / D=8 25.9 / D=16 37.7 ms；4 子×16 B = 一条 cache line）。
  ★ `PQEnt` 必须保持 **16 B**（压成 `{double,uint32}` 有匿名 padding，
  而 `heap_selftest` 用 `memcmp` ⇒ 判据随机失败）。

## 地标下界（ALT）

- 10 地标下界 = 真值 **90~105%**（直线只有 44~74%）；精确下表界 98.0~99.0%，
  **单侧 == 双侧** ⇒ **不需要反向 Dijkstra**。
- ★★ Dijkstra **必须带转向限制 + 跨省缝合**（不缝合抬高 5~12% 就越过真值）；
  负向对照：关缝合 ⇒ 跨省查询全 UNREACHABLE。
- **表已落地**：`lmtable.{h,c}` + `lmbuild_cli` + `scripts/citypairs.py`。
  460×767 格（3 km×2.56 km）、penalty 4045 m，**30 地标 21.2 MB**，构建 ~8 s/地标
  → `products/graph/lm.bin`，**已接进 sync_maps.sh**。heur = 直线与下界**取 max**；
  `lm_tc[dir]` 每次搜索只算两遍（不能放进 heur）；`NAVIMAP_LM=0` 关；没表退回纯直线。
  表存**米**，`mode_time=1` 时同直线按 `H_SPEED_KMH` 换秒。
- ★★★ **地标下界不是严格下界（用户 2026-09-28 拍板"接受并写明"）**：
  ⇒ 定位是**"加速启发式"，不是下界**。`--exact` 在开表时**不再承诺最优**；要真值须 `NAVIMAP_LM=0`。
  ★ 门禁第 45 项 `lm_admissible`：判据故意写成**上界** `开表分钟 <= 无表分钟 + 1`
  （129 vs 128 过；将来修好 128 vs 128 也过；更差才 FAIL）。**负向对照已验**（slack 改 0 ⇒ FAIL）。
  ★★ **判据不该在 bug 修好那天反而报错。**
  ★ 三个假设两个已证伪：**加大 penalty 无效**、**与双向无关**、**不是转向限制**；
  剩余候选：**u 侧要格内 max 不是 min**（50 条：一致 46 / 越界 2）。
  ⇒ 破的是"最优性承诺"，不是"质量"（开表比无表质量好 3.21%）。
- ★ 前提已验：全图边限速**最大 120 km/h < H_SPEED_KMH 130** ⇒ 直线 h 可采纳。
- ★★ **w 的有效贪心度 = w × h/真值**：无表 h 只有 44~74% ⇒ w=1.4 实际 0.7、1.8 才 0.9；
  有表 h 到 92~97% ⇒ 1.4 变 1.33、**1.8 变 1.71（有害）**。⇒ **上地标表必须同时重新定 w。**
- ★★★ **w 的最优值随"地标数/启发式紧度"往下走**：10 地标定 1.3，**30 地标后最优降到 1.25**。
  改地标数 = 改 h 紧度 ⇒ **必须连带重定 w**。
- ★★ **现行定案：30 地标 + `ROUTE_HEUR_W_LM 1.25`**，`heur_w_hi` 也兜底成 1.25（继续关着"撞顶升级"）；
  无表维持 1.4/1.8。30@1.2 只多买 26 分钟但最慢炸到 3783 ms（**别选**）。
- ★★ **"h 更准了中位反而更慢"的机理：基线在过早收工**，不是退化。
  南阳→烟台真最优 609~610 分：基线 2.7 万展开给 649 分，1.3 给 610 分（最优）用 171 万展开
  ⇒ **1.3 用一半代价拿最优解**。
- ⚠️ `RouteOpts` 里写死 `.heur_w = ROUTE_HEUR_W_DEFAULT` 会**把兜底顶掉**（三处都踩过）。
  ⚠️ 关掉升级后**必须同时去掉自适应的空转第一遍**：`two_pass = (try_cap != 0) && (heur_w_hi != w0)`。
  白扔量 = 26/50 条 × 20 万 = 26.5%。
- ★ **数据事实：`nodes.bin` 六成节点出度为 0**（陕西 1031 万/1323 万）且**也没有入边**
  ⇒ 真孤立，不是 bug。⇒ **"节点数"不能当算路的性能基数**，应按"有出边"的 2250 万算。

## PBF 按需解码显示层（src/map/pbfmap.c，2026-10-23）

- `--pbf-display=<sources目录>[:LRU上限]` ⇒ 显示层（面/线要素）运行时从 PBF 解码 + 内存 LRU，
  `lines/areas/polyrefs` **可不落盘**（8 省省 195 MB）。**8 省逐字节 IDENTICAL**（已证）。
- ★ **省粒度而非瓦片粒度**：PBF 的 data blob 平均覆盖全省 **43%** 纬度跨度（北京 621 blob，
  单个跨 0.99°/1.33°，z11 视口仍命中 53%）⇒ 按 blob 跳读收益低于索引成本。
- ★ **不扫第二遍 PBF 取坐标**：`polyrefs` 存的就是 nmbin `nodes.bin` 的节点内部下标
  ⇒ 二分查表即可（省整遍扫描 + 105 MB 坐标数组）。峰值 RSS 1.53 G → 714 MB。
- ★ **下标空间必须复刻 `graph_build`**：refs 收集**要含路网 way 的节点**（它在三分支之前累加）、
  名字池 id 空间要与落盘版一致（路网 way 也要 intern）—— 漏一条就下标错位、坐标全错。
- 解码耗时：天津 0.65 s / 北京 1.6 s / 河北 4.4 s（**同步**，首次进省会停顿 ⇒ 需后台线程）。

## 方法论（做优化前默念）

1. **不凭印象定瓶颈**（已被推翻四次）；分解只能当排序线索，**收益必须实测**。
   ★ 一次哈希查找取决于冷热：热区 23 ns，冷表 186 ns。
2. **交替 A/B 取最小**，别"整组 A 再整组 B"。探针/插桩会污染 ⇒ 量完撤干净。
3. **判别实验的替换版必须保持下游工作量**，否则量出假的大头。
4. 等价性判据不能抽样：`lround` 会掩盖 ULP 差异 ⇒ 全量真实数据逐点比两套实现
   + **定向构造边界点** + 负向对照"必须能失败"。
5. ★★ **归因给的是"占多少"，不是"删掉能省多少"**（已推翻三次）：
   **删一段代码会把它顺带替别人付的钱一起删掉** ⇒ 删某相位前**先用相位表对拍**，
   看 X 是不是**转移**到别处。相位名数组 ↔ 枚举**必须静态断言**。归因须 **≥2 条形状不同的路线**。
6. 判别"访存延迟 vs 算术"：同一份数据把该操作连做 3 次——算术型线性涨，延迟型第 2/3 次几乎免费。
7. ★ **"某阶段的 raster 相同"不等于"该阶段没问题"** —— 标注走 `SDL_RenderCopy`（不进 raster），
   要分别看"自写光栅阶段"与"SDL 调用阶段"。
8. ★ 怀疑"未初始化内存"时**先查对象生命周期**（谁创建、谁销毁、指针是否还活着），
