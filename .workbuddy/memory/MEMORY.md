## 性能口径 + 判据纪律

- **渲染**用 `map_shot` **第二帧**；**算路**用 `route_cli --repeat=N` **丢第 1 次**取中位
  （"搜索 X ms"含反向索引构建，端到端 real 才含图加载）。
- 无 `perf`/valgrind；`clock_gettime` 52 ns ⇒ 插桩会污染（渲染探针自己吃 5~8 ms），量完撤干净再取基线。
- ⚠️ **负载能污染算路耗时一个数量级**（load≈10+swap 满：502→3885 ms，展开数不变）
  ⇒ ★ **布尔判据用展开数/里程/像素，别用耗时**；时间只兜底且取多轮最小值。
- ★★ **A/B 至少 4 轮，每轮都列出来**（§45.7、§47.3 都栽在 2 轮）。
- ★★★ **"手挑几条代表路线"下结论必翻车，已踩 3 次**（§45.7/§47.3/§50.7/§51.4）。
  §50.7：6 条最慢路线说"w=1.2 全面占优"，44 条一跑**中位是反的**（202→690 ms）；
  §51.4：8 条"含一半难走路线"说"快 5.7 倍"，50 条全量是**中位慢 1.8×**。
  ⇒ 连"手挑 8 条+4 轮交替"都不够；样本必须**覆盖形状且成对配对**，报结论前先问"难走/好走各占多少"。

## 数据格式：PBF vs OBF（2026-10-22）

- navimap 只吃 `.osm.pbf`（自写 `src/pbf/` 解码 → 自编 `.nmbin`）；**零 OBF 代码**。
  OBF = OsmAnd 私有格式（文档开放、reader 是 GPL），多段 Map/Address/Routing/POI/Transport，容器层 protobuf。
  **OBF 与 PBF 同源 OSM**，OBF 多出的是 OsmAnd 已做好的建图/分类/归并。
- ★ **磁盘构成实测**：`sources/` PBF 共 **446 M**；`products/` nmbin 共 **4.2 G**，
  但 nmbin 里**显示相关**（tiles+lines+areas+polyrefs）仅 ~19 M/省，
  **94% 是路由图**（nodes/edgelist/edges/rev/osmid ≈ 4 G）
  ⇒ "删 nmbin 省空间"只省得到那 19 M/省，**真吃盘的是路由图**。
- **"直接读 PBF 显示"对显示层可行**（解码成内存结构 + LRU 缓存），对 4 G 路由图不可行（A* 需全图）。
  nmbin 的价值 = 省掉每次启动重解 + 提供 mmap 懒加载。
  ⇒ **nmbin 值得保留，可以不演化 v3**（v3 是可选优化，§32 已暂缓：z9 只 −16 ms 不抵 +139 MB）。
- **不要为 POI 引入 OBF**：`places_build.c` 的 `class_node_tags()` 早已从 PBF 抽
  amenity/shop/tourism/... 节点写进 `place` 表（PLK_POI=11/PLK_FEATURE=12）；
  `labels.c` 的 `kind_max_for_zoom()` 在 z≥15 返回 12 正好覆盖 ⇒ POI 已可见/可搜。
- 授权：借鉴思想+注明出处+不同语言/框架独立实现 = 最干净路径（coordkey.h 已示范）。

## 渲染：定论与"别再试"

- **多省不变量**：多省画面 == 只加载包含方的画面（8 省 vs 只河北 0 差异），可当验收。
  被整省包含的省（`dup_of>=0`）面/路/线全跳过；去重只在"这格瓦片 ≥2 省"时做；**面/线不去重**。
- ★ **"简化几何"一律不成立**，已否决三种，别试第四种：投影前按像素筛顶点 /
  Douglas-Peucker（ε=0.5 就 1.1% 差异且**更慢**）/ 放宽 AREA_DOT_PX。z9 走完整管线的面 **91% ≤5 px**。
- 同样别再试：去掉描边、面要素加 tile 索引、顶点内联进索引、软件预取、缓存上一条
  目起点、合并连续边成折线。**NMBIN 内存布局暂缓**（§32）。★ 贵的是**间接寻址**不是 stride。
- ★ **只有"不画"才省得下来**：SDL 每次绘制调用固定 ~100 ns，与像素数无关；
  `SDL_RenderDrawLines` 不省每条线段开销。换更便宜的画法几乎没用。
- ★★ 自写像素（`src/render/raster.{h,c}`）后：**退化段（两端同坐标）必须画 1 个像素**。
  本机 surface 是 **`SDL_PIXELFORMAT_RGB888`**（Amask=0）。resize 重建 renderer 前必须 `font_drop_textures()`。
- 面要素 55 ms 已逐段量完（投影 21/填充 13/描边 10/访存 6/固定 9/遍历 3），无明显空间。

## 算路：约定与已做

- **默认加权 A\* w = 1.4**（§45 用户拍板）；与 `opt.exact` 是两个独立旋钮。★ 这是**产品行为**。
  ★ 兜底是 `mode_time=1` ⇒ **优化时间不是里程** ⇒ 质量指标必须用"预计 X 分"，
  **不能用里程/绕行系数**。档位：w≤1.2 无损；**1.4 是拐点**；1.5 起真劣化。
- **自适应 w（§45.8）**：第 1 遍基准 w + 封顶 `ROUTE_ADAPT_TRY=20 万`；**在顶内结束的结果与基准 w 逐位相同**，
  撞顶才换 `ROUTE_HEUR_W_HARD=1.8` 重跑。判据是**展开数 < 100 万**。★ 对拍时 `heur_w_hi` 也要设。
- ★★ **加 w 救不了尾部**（§46.2）：1.8→3.0 时间最多再降 1.9×，质量 +9%~+37%，**大连→北京非单调**。
- ★ `RouteOpts` 一律**指名初始化**。★ **热路径严禁 `getenv`**（一次 135 ns），
  调试开关用 `static int f(void){static int v=-1; if(v<0) v=...; return v;}`。
- ★ 拆函数改了共享状态必须恢复：`plan_search` 曾把 w 写进 `r->opt.heur_w` 没恢复 ⇒ `--repeat=N` 第 2 次起假数字。
- **反向索引已落盘** `rev.bin`（8 省 355 MB）；没有/坏了自动现场建。默认只做 O(1) 校验
  （全量 FNV +554 ms 比重建贵，`NAVIMAP_REV_STRICT=1` 开严格）。
- rev.bin v2（存 edge_idx）：**做完、实测否决、已回退**（§44，只值 3%，+146 MB）。
  ★ 每个反向条目 unavoidable 的冷访存就是两次，v1/v2 都是两次，**没有第三次。别再试。**
- **瓦片下标查表化** `tileidx.{h,c}`。★★ **回退带（2e-3 瓦片）必须大于查表误差**
  （墨卡托 `y''∝1/cos²φ`：45° 3.8e-6 → **85° 3.6e-4**）。
- **`SEW_SLOTS`=16384**（§39），容量参数要用**工作集最大**的输入定案。
- `DEFAULT_MAX_EXPAND` 800 万 → **1200 万**（§48.3）：800 万会剪断真实路线
  （郑州→大连要 1133 万展开/15.7 s/2.29 GB）。★ 边际 ~210~290 B/展开。

## 地标下界（ALT）：§48 探针 / §49 Dijkstra / §50 表已接入 heur

- ★★ Dijkstra **必须带转向限制 + 跨省缝合**（不缝合抬高 5~12% 就越过真值）；
  负向对照：关缝合 ⇒ 跨省查询全 UNREACHABLE。
- ★ 不能复用 A* 的 StEnt（3.2 GB 放不下）⇒ 按 (省,节点) 平行数组 cost/arr/prev2 各 4 B，
  同一坐标多省成员靠 **pop 时零代价转移**拉齐。全图 1887 万出堆/12 s/2.6 GB。
- **表已落地（§50，§52 扩到 30 地标）**：`lmtable.{h,c}` + `lmbuild_cli` + `scripts/citypairs.py`。

  没表退回纯直线（不算错误）。表存**米**，`mode_time=1` 时同直线按 `H_SPEED_KMH` 换秒。
- ★★★ **地标下界不是严格下界（§52.8，用户 2026-09-28 拍板"接受并写明"）**：
  ⇒ 定位是**"加速启发式"，不是下界**。`--exact` 在开表时**不再承诺最优**；要真值必须 `NAVIMAP_LM=0`。

  ★ 门禁第 45 项 `lm_admissible`：太原→石家庄，判据故意写成**上界**
  `开表分钟 <= 无表分钟 + 1`（129 vs 128 过；将来修好 128 vs 128 也过；更差 130 vs 128 才 FAIL）。
  **负向对照已验**：slack 改 0 ⇒ FAIL ⇒ 判据有分辨力。工具 `scripts/lmadmissible.py --slack=N`。
  ★★ **判据不该在 bug 修好那天反而报错。**
  ★ 三个假设两个已证伪：**加大 penalty 无效**、**与双向无关**、**不是转向限制**；
  剩余候选：**u 侧要格内 max 不是 min**。50 条实测：一致 46 / 越界 2（距离口径 +1.9%）。
  ⇒ 影响面：发货 w=1.25 本就不承诺最优，且开表比无表质量好 3.21% ⇒ 整体仍正收益；
  真正破的是"最优性承诺"（`--exact`/`restr_ab` 对拍依赖它）。
- ★ 前提已验：全图边限速**最大 120 km/h < H_SPEED_KMH 130** ⇒ 直线 h 可采纳。
- ★★ **w 的有效贪心度 = w × h/真值**：无表 h 只有 44~74% ⇒ w=1.4 实际 0.7、1.8 才 0.9；
  有表 h 到 92~97% ⇒ 1.4 变 1.33、**1.8 变 1.71（有害）**。⇒ **上地标表必须同时重新定 w。**
- ★★★ **w 的最优值随"地标数/启发式紧度"往下走**（§51.4 → §52 两次印证）：
  10 地标定 1.3，**扩到 30 地标后最优降到 1.25**。改地标数 = 改 h 紧度 ⇒ **必须连带重定 w**。
- ★★ **现行定案（§52，用户拍板）：30 地标 + `ROUTE_HEUR_W_LM 1.25`**，`heur_w_hi` 也兜底成 1.25

## 状态表（§43.4 + §47）

## 图集按需加载（2026-10-22 新增，src/map/mapset.c）

- 目标：运行时只 mmap 视口所在省份，滚出即卸载 ⇒ 少占内存/句柄。
- **`MapSrc` 加 `loaded` 标志**；`src_open` 拆成 `src_open_files`（只开文件）+ `src_open`（置身份），
  重载走 `src_open_files`，**身份与 `dup_of` 保留**。`src_unload` 只关文件+释放 area/line bbox，
  **保留 name/dir/bbox/dup_of**。
- ★★ **省份下标必须恒定**（槽位=省 id，**绝不重排 `srcs[]`**）：`prov` 写进了路线结果与 RNode
  （maneuver.c、window.c 按 `ms->srcs[prov]` 取路名/坐标），重排会悬垂。
- 新增 `mapset_set_view(ms, vb)`（渲染每帧调，视口 e7 bbox + 50% 边距）、
  `mapset_ensure_loaded(ms, prov)`（按需重开）。
- 迭代函数（`mapset_query_tile`/`mapset_detail_prov`/`mapset_totals`/coverage）跳过 `!loaded`。
  ★ `coverage.c` 的 bbox 命中循环**不能**跳过 `!loaded`（bbox 卸载后仍在），
  否则"视口外查询"会误报无数据 ⇒ 命中后 `mapset_ensure_loaded` 再查瓦片。
- ⚠️ `const MapSet*` 传给 `mapset_ensure_loaded` 要写 `(MapSet*)` 强转，
  否则 `-Wdiscarded-qualifiers` **零警告门禁 FAIL**（coverage.c 踩过一次）。
- 实测（北京 z11，8 省图集）：**加载 3 省 / 卸载 5 省**；换中心到石家庄会换省；
  z7 大范围时全省保持加载。`map_shot --graph=products/graph` 可复现。

## 方法论（做优化前默念）

1. **不凭印象定瓶颈**（已被推翻四次）；分解只能当排序线索，**收益必须实测**。
   ★ 一次哈希查找取决于冷热：热区 23 ns，冷表 186 ns。
2. **交替 A/B 取最小**，别"整组 A 再整组 B"。探针/插桩会污染 ⇒ 量完撤干净。
3. **判别实验的替换版必须保持下游工作量**，否则量出假的大头。
4. 等价性判据不能抽样：`lround` 会掩盖 ULP 差异 ⇒ 全量真实数据逐点比两套实现
   + **定向构造边界点** + 负向对照"必须能失败"。
5. ★★ **归因给的是"占多少"，不是"删掉能省多少"**（§40.2/§44，已推翻三次）：
   **删一段代码会把它顺带替别人付的钱一起删掉**。
   ⇒ 删某相位前**先用相位表对拍**，看 X 是不是**转移**到别处（~1% 跳到 ~10% 就是它）。
   用 SIGPROF 是因为插桩计时不可信；**双份法只准"计算型"，访存型全被测成 0**。
   相位名数组 ↔ 枚举**必须静态断言**。归因必须做 **≥2 条形状不同的路线**。
6. 判别"访存延迟 vs 算术"：同一份数据把该操作连做 3 次——算术型线性涨（+200%），
   延迟型第 2/3 次命中同一 cache line 几乎免费。

## 优先队列（§37/§43.3）

- `src/route/pqueue.h`，**四叉堆 `PQ_D=4`**。★ 别再调叉数：D=2 36.4 / D=3 24.7 /
