## 坐标系参数修订：西安80 从"仅换椭球"改成有出处的全国 3 参数（J 先生问"公开资料没有吗"）

     全国统一 3 参数 **(−104.57, −45.94, +5.30)**；公式 `[XYZ]84=[XYZ]80+Δ`

     平均经向 8.20 m / 纬向 4.21 m，最大 14.73 / 9.23 m。

## 三个扩展入口：接口做实并可验证（J 先生："留待以后再做，记得留好接口"）

- 原则：接口不是 TODO 注释，而是**真实现 + 自测能跑**。将来拿到数据喂进来即生效，
  不用再动算法。全部是进程内设置、不落盘，`datum_reset_params` / `datum_grid_clear` 恢复出厂。
- 入口① 重合点（官方附录A）：`datum_solve_seven_param(DatumTie[], n)` → 最小二乘解 7 参数
  → `datum_set_seven_param` 装回去。n<3 → -1，奇异 → -2。
  ★★ **必须做列均衡**：旋转列按 µrad、尺度列按 ppm（未知数乘 1e-6）。否则设计矩阵
  "平移列≈1" vs "旋转列≈6.4e6" 量级差 7 个数量级，法方程条件数 ~1e13，double 下
  平移解被污染到毫米以上。缩放后条件数降到几十 ⇒ 解算还原误差 < 1 mm、RMS 5.6e-10 m。
- 入口② 图幅改正量（官方 1:5万 正解）：`DatumGridDesc` + `datum_grid_set/clear/active`

  双线性内插、格网外 clamp 不外推。CLI `--datum-grid=<file>` 端到端可喂数据。
- 入口③ 局部经验值：`datum_set_local_offset(id, lat, lon, dn, de)` 按该点东/北单位向量

## 「全国甚至全球的参数会是多组吗」——查证全球惯例后确认设计（J 先生提问）

- 是，多组是全球常态。最好类比 = **北美 NAD27**：EPSG 注册 **85 条** NAD27→WGS84
  变换（78 在用 + 7 弃用），**没有唯一全国值**：若干全国条目（15851 NADCON 网格
  5 m / 加拿大 NTv2 1693 2 m / 7 个 HARN 全国 1.5 m）+ 43 条州/省级 1.5 m 参数。
  BJ54 在 EPSG 6 条（全油气局部）；XA80 零条。
- XA80 无区域变换的根因：它是**过渡性基准**——EPSG:4610 remarks 原文
  "Replaces Beijing 1954 (CRS code 4214). Replaced by CGCS2000 (CRS code 4490)"，
  1980 起用、2008 后全国转 CGCS2000 ⇒ 没人投入做全国区域变换测量。
  而美国能有 85 条，是**海量控制点堆出来的**（每州 HARN 站），不是拟合出来的。
- ★★ 关键演进规律：美国**没有停在"多组参数让人选"，而是走到格网**
  （NADCON/NTv2：全国 5 m / 州级 1.5 m）——与中国官方方案（1:5万图幅改正量 +
  双线性内插）同一条路：**参数法 → 格网法**。死结在"谁来选分区"：用户常不知道
  自己在哪个拟合分区，选错代价 15.8~27.0 m > 全国值最大误差 14.7 m。
  格网无歧义（按坐标自动取值、边界=格网间隔）、够密即连续改正量场。
- ⇒ 本项目设计确认：**单组全国参数（~15 m）+ 入口②格网接口**。若将来拿到的是
  "某省 7 参数"而非格网，入口①/③也能装，但优先级 格网 > 分区参数。
  决策记录已写进 datum.c 顶部注释（含 NAD27 85 条与格网演进路径）。

### 本轮五个新教训（已进 MEMORY.md）

1. ★★★ **编译期 PATH 放 Qt bin ⇒ gcc 静默死**：`/d/Qt/6.11.2/mingw_64/bin` 里有另一套
   MinGW 运行期 DLL（libstdc++-6 等，版本对应 Qt 自带旧 gcc）。排在 ucrt64 前时
   cc1plus 加载到不匹配的 libstdc++ ⇒ 退出码 1、**stderr 全空**，连 `int main(){}`
   都编不过。分辨特征：**C 文件能编过、C++ 全灭**（cc1 不需要 libstdc++，cc1plus 需要）。
   诊断法：`try()` 矩阵实测各组 PATH；Defender 日志无检出记录 ⇒ 排除 Defender。
   修：`build_win.sh` 的 CLEAN_PATH 与 `cc_retry.sh` 的 MSYS_PATH 都去掉 Qt bin；
   Qt bin 只在**运行期**加（regress.sh `qt_run()`）。
2. ★★ **checkable 按钮的 `toggled` 会递归**：`m_trackBtn` 的 toggled 连回
   `toggleTrackPanel()`，内部再 `setChecked()` ⇒ 再发 toggled ⇒ 无限递归，每层
   refreshTrackPanel 建/删控件 ⇒ 栈耗尽 ⇒ **在 `RtlAllocateHeap` 里 SIGSEGV**
   （与 Defender 杀进程/堆损坏表现一模一样）。修：`QSignalBlocker`。
   定位法：写两个最小复现（QLabel / 面板+菜单栏+Dock+样式表）**都不崩** ⇒ 排除框架，
   回头插桩才看到 "refresh done/visible" 重复上千次。
   ⚠️ 顺带删掉了一条**错误结论**注释（"QListWidget 在 offscreen 下崩"）——错归因比没归因更糟。
3. ★ **`isVisible()` 对未 show 的子控件恒 false** ⇒ 浮层贴位用 `!isHidden()`
   （`--shot-track` 时序正是"先开面板后 show"）。负向对照：改回 isVisible ⇒
   `ASSERT-FAIL 轨迹面板没贴到右栏左边（pos=0,0 340x190 画布 1280x779 右栏 1146）`、RC=1。
4. ★ **面板定位判据不能与窗口尺寸耦合**：`pp.x() > 画布宽/2` 在 `--w=900` 下假红
   （340px 面板左沿落到中线左侧）⇒ 改成"右缘贴住右栏左缘（6px 间距）+ 不压右栏 +
   不越左沿"，任意窗口尺寸都成立。**判据要盯住被修的那个性质，别顺手写个更强但更脆的。**
5. 导入幂等：库里轨迹按 name 替换、收藏按 (name,lat,lon) 查重（`gpx_db_find_fav`），
   内存侧同步去重；sqlite rowid 复用 ⇒ 删 track 必须同时删 tpoint 子表。
